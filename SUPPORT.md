## Asking a question

Open a [GitHub Discussion](https://github.com/KaiZeHuang/vernier/discussions) —
use the **Q&A** category. Discussions are searchable, so the next person with the
same question finds your answer instead of asking again.

Please **do not** open an issue for usage questions; issues are for defects and
concrete feature proposals.

## Reporting a bug

Use the [bug report template](.github/ISSUE_TEMPLATE/bug_report.yml). The single
most useful thing you can attach is the **exported scan report** from the app's
records page, with anything you consider sensitive redacted.

## Requesting a feature

Use the [feature request template](.github/ISSUE_TEMPLATE/feature_request.yml).
Tell us the problem before the solution — a good problem statement survives a
change of design, and this project changes design often.

## Reporting a security vulnerability

Do **not** use issues or discussions. See [SECURITY.md](SECURITY.md) for private
reporting.

## Response expectations

This is a personal project maintained in the maintainer's spare time. There is no
SLA. Expect a reply within a few days, and expect longer for anything that needs
a device to reproduce. Silence is not dismissal; it usually means the fix needs
hardware that is not on the desk.
